TL;DR

The path is OrderTab → /api/orders/place (Next.js) → POST /orders/place (FastAPI) → 8-stage validation pipeline → subprocess (xenon-ib-place-order) → IB Gateway → ack persisted via orders_store.mark_submitted → activity poller mirrors fills/external-modify back to Postgres → UI re-renders from the next /orders GET (no live WS push for order events; WS is price-only).

The most fragile parts (verified 2026-05-02): (1) no continuous PENDING reaper — subprocess hangs leave phantoms until restart (§13.11); (2) subprocess concurrency unbounded — clientId range 20–49 exhaustible under load (§13.12); (3) the in-process bypass class — _orders_*_from_body and the submit_combo wizard route both reproduce gates inline (§13.13); (4) cancel/modify clientId scoping — pool can see but not cancel; (5) fill-to-toast latency up to ~120 s from double-polling — order-event WS push would compress this to sub-second (§13.15); (6) late-arriving CommissionReport coupling; (7) the TWS-cancel-not-mirrored gap.

Architectural Concerns

Cross-reference: docs/reference/order-path-incident-history.md table rows correspond to numbered incidents in the markdown. The 6+ recurring patterns:

  1. In-process bypass class — _orders_*_from_body helpers skip route Depends. Caused PR #34 / #47 / #61 regressions. Guards: scripts/checks/order_path_caller_allowlist.py, scripts/checks/no_json_fallback_on_order_path.py.
  2. HTTPException dict-detail trap — wraps under body.detail.reason_code; UI toast reads body.reason_code top-level. Always use JSONResponse(content={...}) for new error mappings.
  3. quote_token saga — re-shipped + reverted twice (PR #34/#35, #47/#48, finally 654d72d2). Backend mint+verify still wired; UI never attaches. Partially-dead code.
  4. TWS-cancel mirroring gap — register_from_snapshot does not transition WORKING → CANCELLED; naive disappearance-detection misclassifies fills. Phantom rows until restart.
  5. Asymmetric writers of order_fills.metadata — record_external_fills, single_leg_rehydrate, record_fill populate metadata with different richness. Incident #16 surface.
  6. user_id="local" hardcoded — blocks multi-tenant; idempotency key collision risk if anything ever goes multi-user.
  7. Substring CI guard — fragile to obfuscation; AST upgrade tracked as C-7.
  8. Modify race on subprocess failure — DB sequence advances, IB doesn't; applied_sequence in 503 body lets client counter sync.
  9. permId race — Trade.order.permId == 0 until openOrder ack; the place subprocess sleeps 2s/5s as a coarse-grained workaround. Downstream rehydrate / BAG aggregation must poll until non-zero.
  10. No continuous PENDING reaper (§13.11) — PENDING_TIMEOUT_SECONDS = 60 (single_leg_rehydrate.py:31) is consulted only during rehydrate_on_boot. The activity poller does NOT sweep stale PENDING rows. Subprocess hangs leave client_attempt_id held; retries silently no-op as duplicate. Mechanical fix: 30 s background UPDATE order_submissions SET state='FAILED' ... WHERE state='PENDING' AND updated_at < now() - interval '60s'.
  11. Subprocess concurrency unbounded (§13.12) — order place / modify / cancel calls have no semaphore (compare UW OI's Semaphore(3) at server.py:810). ClientId range 20–49 = 30 IDs; 30 concurrent place attempts can exhaust the range with no fairness or queueing. Fix: asyncio.Semaphore(20) + IB_BUSY 503 + counter metric.
  12. submit_combo parallel order surface (§13.13) — the wizard route /orders/wizard/{session_id}/submit reaches combo_wizard/session.py:293, which is a second order-creating entry that reproduces the 8-stage gates inline. Any change to the place-route gate sequence must be mirrored here, or the wizard becomes a regression hazard. Future: extract the pipeline as a pure async function and invoke from both surfaces.
  13. acknowledge_limit_override audit fragmentation (§13.14) — limit-band overrides land in order_events (server.py:2864); regime overrides land in regime_overrides. An audit query for "all overrides on this account" must hit both tables. Cleaner schema: extend regime_overrides with kind ∈ {regime, limit_band} and unify the writer surface.
  14. Activity-poller latency budget (§13.15) — XENON_IB_ACTIVITY_POLL_S default 60 s + UI /orders poll = up to ~120 s fill-to-toast latency. Single largest user-visible latency. Fix: extend the existing price WS surface (web/lib/usePrices.ts:354) with an order channel; emit on mark_submitted / mark_terminal / record_fill.

Known Issues + Next Steps

Punch list, ranked by risk × impact (this version reflects a 2026-05-02 verification pass — Tier 1 items 1–4 were under-emphasized in the original draft; full detail in markdown §14):

Tier 1 — reliability gaps with user-visible failure modes

  1. No continuous PENDING reaper (§13.11) — subprocess hangs leave rows stuck PENDING until the next FastAPI restart. Same client_attempt_id retries silently no-op. Mechanical fix: 30 s background sweep, pure Postgres.
  2. Subprocess concurrency unbounded (§13.12) — clientId range 20–49 (30 IDs) is exhaustible under load. Fix: asyncio.Semaphore(20) + IB_BUSY 503 + counter metric.
  3. TWS-cancel not mirrored — phantom WORKING rows until restart. Disambiguate via order_fills for the same (perm_id, scope) + idle-grace window.
  4. No order-event WS push (§13.15) — fill-to-toast latency budget up to ~120 s (60 s server poll + 60 s UI poll). Extend the existing price WS surface with an order channel.

Tier 2 — audit / consistency / parallel-surface parity

  1. C-2.2 combo modify cancel-then-place — explicit "CRITICAL" message but no rollback. Persist legs in order_submissions.metadata (or sibling combo_legs) and auto-replay on failure.
  2. C-2.3 modify override audit — _run_modify_regime_gate override path does not write regime_overrides. override_supported: false is the current honest signal.
  3. acknowledge_limit_override audit fragmentation (§13.14) — limit-band overrides land in order_events, not regime_overrides. Extend regime_overrides with kind ∈ {regime, limit_band} and unify the writer surface.
  4. submit_combo gate parity (§13.13) — wizard surface is a second order-creating route. Audit it line-by-line against the 8-stage pipeline and extract a shared async function.
  5. order_fills.metadata writer consolidation — incident #16 follow-up. Three writers, different richness; root cause of the "Stock" structure-label fall-through.

Tier 3 — long-tail follow-ups (already on backlog)

  1. C-5 hedge registry — pull from docs/trading/options-structures.json instead of hardcoded frozenset.
  2. C-6 user_id="local" — idempotency key risk, multi-tenant blocker.
  3. C-7 substring CI guard → AST call-site analysis.
  4. Modify race — DB sequence advances, IB doesn't on subprocess failure. Cosmetic but worth flagging.
  5. quote_token partially-dead — both sides wired, no UI caller. Either delete or re-ship after re-doing #34/#47 analysis.
  6. tick stub at 0.01 — reqContractDetailsAsync not plumbed; acceptable until edge instruments dominate the trade mix.

Source-of-truth files cited throughout. Read docs/reference/order-path-incident-history.md first when touching this surface; append a row when shipping a non-trivial fix.
