# Order-Path Incident History

Chronological log of bugs, regressions, and structural fixes in the order
placement / cancel / modify / blotter / rehydrate path. Use this as the
first thing you read before touching any of those modules — many of the
guardrails in place today exist because of a specific incident.

**Window:** 2026-04-21 (PR #27) onward. Earlier work pre-dates the
Postgres mirror and is mostly archaeological.

**How to use this doc:**

- Browse the table to spot patterns before introducing a change in the same area
- Cross-reference the prevention column with whatever new test you're writing — duplicate coverage isn't useful
- Add a row when shipping a non-trivial order-path fix (one row per _root cause_, not per commit)

## Recurring patterns to watch for

These have caused two or more incidents and are still partially open:

1. **Per-flow gating that bypasses central enforcement.** UI buttons / in-process callers can skip route-level `Depends`. Server-side preflight + caller allowlist (`scripts/checks/order_path_caller_allowlist.py`) are the durable fix. See rows #4, #6, #12.
2. **Derived data not reactive to upstream metadata updates.** `xenon.trades` was aggregated before `realized_pnl` arrived; structure label fell through to `"Stock"`; leg fills written without strike/right because the IB Fill contract was incomplete. Self-heal aggregation + write-time enrichment are the durable fixes. See rows #14, #15, #16.
3. **Asymmetric writers populating the same row.** `record_external_fills`, `single_leg_rehydrate`, `record_fill` all write `order_fills.metadata` with different richness. Consolidation is open work. See rows #14, #16.
4. **Hard-coded placeholders survive past their intended lifetime.** `tif="DAY"` shipped in production for months because there was no follow-up task. CI lint that scans routes for string literals matching IB enum values would catch the next one. See row #16.
